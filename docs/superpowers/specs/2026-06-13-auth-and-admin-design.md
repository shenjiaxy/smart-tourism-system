# 用户登录与管理员系统设计

## 目标

为现有智能旅游系统增加真实登录鉴权，并将普通用户端与管理员端分开。普通用户登录后使用现有旅游功能；管理员登录后默认进入独立后台，管理用户和旅游日记。

## 架构

- 后端新增 `AuthService`，从现有 `users` 表校验账号密码，生成随机内存会话令牌。
- 客户端通过 `Authorization: Bearer <token>` 发送令牌。
- `/api/auth/login` 与 `/api/health` 保持公开，其余业务接口要求登录。
- `/api/admin/*` 额外要求 `role=admin`。
- 前端新增 Pinia 登录状态、Axios 令牌注入、401 清理会话和 Vue Router 权限守卫。
- 同一 Vue 应用提供两套独立布局：普通旅游端使用现有顶部导航；管理员端使用后台侧栏。

## 用户端

- `/login` 提供账号密码登录，并显示普通用户与管理员演示账号。
- 普通用户登录后进入 `/`，可使用推荐、路线、设施、日记和美食功能。
- 顶部显示昵称、角色和退出按钮。
- 创建日记、日记评分使用当前登录用户 ID，不再固定为用户 1。
- 普通用户访问 `/admin` 时自动回到首页。

## 管理员端

- 管理员登录后进入 `/admin`。
- 后台总览展示用户、管理员、景区、节点、道路、日记和美食数量。
- 用户管理展示账号、昵称、角色、注册时间，并允许在普通用户和管理员之间调整角色。
- 日记管理展示作者、目的地、热度、评分和发布时间，并允许删除日记。
- 管理员可以通过“返回用户端”查看普通业务页面，也可以退出登录。

## API

- `POST /api/auth/login`
- `GET /api/auth/me`
- `POST /api/auth/logout`
- `GET /api/admin/overview`
- `GET /api/admin/users`
- `PUT /api/admin/users/:id/role`
- `GET /api/admin/diaries`
- `DELETE /api/admin/diaries/:id`

## 安全与错误处理

- 登录查询使用 SQLite 预编译语句，不拼接用户名和密码。
- 会话令牌使用随机数生成，不包含密码。
- 密码暂时兼容数据库现有明文数据；本次不迁移密码哈希，避免破坏已有演示账号。
- 登录失败统一返回 401，不区分用户名不存在或密码错误。
- 缺少或无效令牌返回 401；普通用户访问管理员接口返回 403。
- 不允许管理员修改自己的角色，避免当前会话意外失去后台权限。

## 测试与验收

- 后端测试覆盖普通用户登录、管理员登录、错误密码、令牌解析和管理员权限判断。
- 前端构建与现有测试全部通过。
- HTTP 验收覆盖未登录拒绝、普通用户业务访问、普通用户后台拒绝和管理员后台访问。
- 浏览器分别使用普通用户和管理员账号登录，确认进入不同界面并验证退出登录。
